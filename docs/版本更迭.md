# Loop 版本更迭

## v0.1 文档与对话

项目选择、结构化问题深究、五份核心 Markdown、编辑/哈希/批准门禁、基础 SQLite 事件记录和三视图工作台。

## v0.2 单 Agent 执行

OpenAI/DeepSeek 适配、文件与命令工具、分级审批、预算、SSE 和失败恢复。

## v0.3 多 Agent

任务树、并发调度、Git worktree、子 Agent 结果文档、Lead Main 集成和全局验证。

## v0.4 可靠恢复

Markdown 检查点、顺序 Main 换代、并行模块 Main、租约、事件重放和幂等恢复。

## v0.5 安全与自动化

全自动模式、硬安全线、junction/符号链接防逃逸、Windows 凭据管理器和完整审计。

## v1.0 稳定版

完成性能、安全和恢复测试；稳定三种 UI；提供安装、升级、数据迁移和故障排查文档。

## 本次验证证据

- `npm.cmd test`：覆盖 API、文档哈希、v7 迁移/动作/预算/generation、安全注入、精确编排、UI 状态和 diff；测试数量以当前 CI 输出为准。
- `npm.cmd run build`、`npm.cmd run typecheck`、`npm.cmd run lint` 全部通过。
- 应用内浏览器在 1280×720 和 390×844 验证工作台/流程/IDE、活动面板、自动路由、设置、运行菜单与移动抽屉；无 console error/warn，无横向页面溢出。

## 下一阶段优先级

1. P0 恢复体验：动作结果未知、冲突和基线漂移的人工核对向导。
2. P0 真实试点：至少 20 个 Git Node/TypeScript Web 任务，记录接受率、时间、费用和干预次数。
3. P1 规模验证：万级事件、百任务、长文档和 16 并发的性能/内存/磁盘压测。
4. P1 可运维性：完整生成式 OpenAPI、迁移回滚演练、诊断与故障排查文档。
5. P2 产品扩展：桌面封装、图片输入、远程执行和多用户在新的威胁模型批准前保持冻结。

## 兼容与迁移

- SQLite schema 使用单调递增版本和事务迁移，不自动降级。
- Markdown front matter 的 `loop_schema` 独立于应用版本；旧 schema 先转换草稿，用户确认后批准。
- Provider 模型 ID 始终由用户配置，升级应用不静默更换模型。
- 后续版本再开放图片输入、跨平台桌面封装、远程执行、多用户和更多供应商。
