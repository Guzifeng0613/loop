# Loop 功能

## 项目与运行

- 添加并验证本地项目目录，展示 Git 状态和文档门禁状态。
- 创建运行、暂停、继续、取消、重试和导出运行记录。
- 默认预算为 200 次模型调用、500 万输入 token、50 万输出 token、120 分钟；接近任一上限时暂停派发。
- 技术 Alpha 默认并发 2、树深度 1、Agent 总量 12、直属任务 8；固定模型为稳定入口，自动路由与更高并发标记为实验。

## 深究与确认

每轮对话返回五个结构化区域：已理解事项、具体理解、未理解事项、当前假设、需要确认的问题。用户回答后继续循环；只有用户批准规范后才允许拆分和执行。

本地演示分析器只能由用户明确勾选，保证界面与状态机仍可验证，但不会伪装为真实模型结果，也不会在真实供应商不可用时自动回退。

## 文档门禁

- 读取、编辑、比较和批准项目 Markdown。
- 批准时记录内容哈希与版本；修改批准文档时运行转为 `doc_review`。
- 任务携带 `DocReference[]`，引用过期时不允许执行工具。

## Agent 编排

- 固定模式：整次运行只使用用户选择的模型。
- 自动模式：用户指定 Lead 模型与允许供应商，Lead 可以为子任务选择模型。
- 建立带父子关系、依赖、作用域、租约和验收条件的任务树。
- 子 Agent 完成时输出变更摘要、文档引用、命令、测试结果、风险和后续建议。
- 支持顺序 Main 换代、并行模块 Main、上下文检查点、幂等恢复和限流退避。
- 自动模式单独保存 Lead 模型与子任务允许供应商列表；固定模式把允许列表收敛为所选供应商。

## 工具与审批

- 首版工具：列目录、读文件、文本搜索、原子写文件、结构化验证命令、读取 Git 状态和管理 worktree。模型不得提交原始 shell；只接受 `git_status`、`git_diff`、`npm_script`、`search` 的严格参数对象。
- 工具策略返回允许、需要审批或拒绝，并解释命中的规则。
- 审批请求可批准一次、批准同类规则或拒绝；结果进入审计事件。仓库自定义 `npm_script` 即使位于白名单也必须逐次批准，因为脚本内容属于不可信代码。
- 同类批准仅在当前运行、同一能力、资源和 `ruleKey` 范围内生效；高风险、依赖变更、联网、删除、Git 发布、未知命令和最终合并强制逐次批准。

## 交付与用户验收

- 当前 generation 的全部根任务必须各自具有同 SHA 的已验证结果和 artifact 才允许进入隔离 integration branch；用户批准后系统运行实际存在的全局验证脚本，但不会自动修改用户当前分支。
- 验证通过后进入 `awaiting_acceptance`，展示变更文件、提交、验证命令、结构化任务结果、风险、未决事项和实际费用。
- 用户可选择保留分支、明确合并、要求修改或放弃。最终合并还会生成一次性审批，锁定集成 branch/commit、根工作区目标 branch 和基线；要求修改会创建新 generation 并回到文档评审，只有保留或合并后才进入 `completed`。

## 异常与恢复

- API 限流采用带抖动的指数退避；认证错误立即暂停并提示设置。
- 服务器重启后从事件序号、generation、动作状态、服务端幂等键和 worktree artifact 恢复；执行效果未知的动作暂停等待人工核对，不自动重复执行。
- SSE 断线通过 `Last-Event-ID` 重放遗漏事件。
- 文档冲突、Git 冲突或预算耗尽均进入可恢复暂停状态，不静默丢弃结果。

## 验收条件

- 能从问题输入走完澄清、文档批准、拆分、Agent 执行、验证和完成状态。
- 批准文档改变后，未开始及运行中的相关任务被安全暂停。
- 固定模型与自动路由都可工作；模型密钥不会进入 SQLite、日志或响应。
- 路径逃逸和未经批准的高风险命令被阻止。

## 已落地补充

- 运行菜单已经提供 Markdown 导出、失败重试和取消；活动面板展示真实追加事件、工具输出、恢复线索与预算消耗。
- 设置页可修改并发、Agent 总量、直属任务上限、树深度、自动模式和四类运行预算。
- IDE 支持保存前差异查看，并折叠长文档中未变化的行；文档保存后仍按哈希使既有批准失效。

## 功能优化方向

1. P0：增加动作结果未知、Git 冲突和基线漂移的可视化核对/恢复向导。
2. P1：为活动流增加类型筛选、搜索和大输出详情展开；导出包附带 generation、检查点和验证证据索引。
3. P1：增加任务级重试、审批规则撤销和 worktree 清理入口。
4. P1：建立至少 20 个真实任务的简单模式/多 Agent 对照基准。
5. P2：图片输入、远程执行、多用户协作和更多供应商保持显式扩展项。
