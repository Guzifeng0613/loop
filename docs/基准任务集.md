# Loop 真实任务基准集

## 记录字段

每个样本同时以简单模式和多 Agent 模式运行，记录：任务名称、仓库类型、初始提交、验收命令、首次成功、最终验收、耗时、费用、模型调用数、输入/输出 token、用户干预次数、审批次数、自动重试次数、阻塞到恢复耗时、恢复决定、恢复是否成功、SSE 重放延迟、worktree 峰值占用、失败原因和人工修复备注。

## 对照规则

- 默认保持并发 2、树深度 1、Agent 总量 12、直属任务 8，不因试点提高默认能力。
- 样本必须来自真实 Node/TypeScript/Web 仓库，且每个任务有明确验收命令。
- 多 Agent 只有在验收率、耗时或干预次数显著优于简单模式后，才进入默认策略评审。
- B01–B05 为简单任务，B06/B18/B20 覆盖断线与验收，B11 覆盖审批，B16 覆盖 worktree，B19 覆盖重复请求；每轮另对 B06、B16、B20 注入重启、基线漂移和预算暂停。
- 同一任务的两种模式使用相同初始提交、模型、预算和验收命令；失败样本不得静默剔除。

## 晋级门槛

多 Agent 进入默认策略评审必须同时满足：最终接受率不低于简单模式、P50 交付时间至少降低 15%、P50 人工干预不增加、P50 费用增幅不超过 30%、恢复失败率低于 5%。少于 20 个有效配对样本时不作默认策略调整。

恢复闭环进入稳定版必须满足：所有注入中断均提供可继续或可放弃路径；未知动作不自动重放；恢复决定审计覆盖率 100%；重复恢复请求不产生重复预算结算或重复副作用。
