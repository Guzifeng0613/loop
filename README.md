## 开发指南

### 代码规范

- 提交前请确保代码通过格式化与静态检查。
- 建议遵循统一的代码风格（待补充具体工具，如 ESLint / Prettier / Black / Checkstyle）。

### 提交规范

本项目建议遵循 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/v1.0.0/) 规范：

| 类型 | 说明 |
| --- | --- |
| `feat` | 新增功能 |
| `fix` | 修复缺陷 |
| `docs` | 文档变更 |
| `style` | 代码格式调整（不影响功能） |
| `refactor` | 重构（既不是新增功能，也不是修复缺陷） |
| `perf` | 性能优化 |
| `test` | 新增或修改测试 |
| `build` | 构建系统或外部依赖变更 |
| `ci` | CI 配置变更 |
| `chore` | 杂项（不修改源码或测试） |
| `revert` | 回滚提交 |

提交信息示例：

```bash
git commit -m "feat: add user login module"
git commit -m "fix: resolve null pointer on empty input"
```

### 分支管理

- `main`：稳定的生产分支，始终保持可发布状态。
- `feature/<name>`：新功能开发分支。
- `fix/<name>`：缺陷修复分支。
- `docs/<name>`：文档更新分支。

## 贡献指南

欢迎参与贡献！请按以下步骤提交：

1. Fork 本仓库。
2. 基于 `main` 新建分支：`git checkout -b feature/your-feature`。
3. 完成开发并提交：`git commit -m "feat: add your feature"`。
4. 推送分支：`git push origin feature/your-feature`。
5. 在 GitHub 上发起 Pull Request，并描述改动内容与动机。

> 提交 PR 前，请确认代码已通过测试与代码检查，并在必要时补充文档与测试用例。
